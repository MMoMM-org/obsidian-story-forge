Story Forge — What optional plugins add · capability disclosure L12a–L12g · T7.4 · draft for sign-off

Why this page exists. PRD F8 asks for a one-time screen that lists each optional plugin, marks it core or community, and says concretely what is lost without it. After dismissal it must stay reachable from settings, through the Library link "What optional plugins add…" (mockups-library.html P14, already in SettingsTab.ts but inert). ADR-36 sets the line: a core plugin may be suggested once and dismissibly, and a community plugin is listed and never nagged. This page draws that screen, the one core hint, and the settings entry point.

How to read this file. Same tokens and modal shell as mockups-catalog.html (L10) and mockups-import.html (L11). Light is the default, the toggle switches every figure, and L12g is always dark. Tags: F8 / ADR-36 / today = fixed by the spec or already shipped; S# = proposed here. The plugin list is the code's list, not a wish list. Story Forge touches exactly three optional plugins: Bases (core), Dataview (community, with its JavaScript setting) and metadata-menu (community, and only its file format). Properties, Calendarium, Longform and meta-bind are not used by any code, so they are not on the screen. The evidence for every row is an HTML comment at the top of this file.

Proposals — your answer needed (recommended default in each)

  1. S1 — Modal or tab, and when it first appears. (a) A modal, the same one from both entry points; (b) a workspace tab (an ItemView); (c) a settings section only. Recommended: (a). It is read once and closed, so it should not take a place in the workspace layout or be restored on the next launch. It appears the first time the Anvil or the Workbench opens after install or upgrade, not at plugin load, so it never interrupts Obsidian starting up. Closing it in any way (Got it, ✕ or Escape) dismisses it for good. A new id in dismissedHints (operational state in data.json) records that.
  2. S2 — Where the core hint lives, and what it says. The hint already exists (basesHint.ts): it shows only when Bases is off, in the Anvil's Codex tab, above the pills. Recommended: keep it in that one place, keep it once and dismissible, and reword it from "Enabling the core Bases plugin adds more Card options." to The core Bases plugin is off. Turn it on to draw .base collections and to use Story Forge Cards in your own .base files. The old text undersells it: what is lost is whole collections, not options. The per-collection "<name> needs Bases" empty state stays. It states a cause where something is missing, which is not a suggestion. The Workbench's legacy Enable Bases button (SidebarView.ts) goes, because it is a second suggestion and uses the non-public app.setting (see S4). Its cause text stays.
  3. S3 — Live status on each row. (a) Show it, read when the screen opens; (b) no status, a static list. Recommended: (a), with only states the code can actually tell apart. Bases: On / Off (and Not in this Obsidian version, unreachable on 1.12.7+). Dataview: Active / Not active. Story Forge sees loaded plugins only, so "disabled" and "not installed" look the same, and the screen does not pretend otherwise. Its JavaScript setting is shown on a second line. metadata-menu: the FileClass files found, since Story Forge reads those and never checks the plugin. Absence is drawn in neutral grey, never amber or red. The status is information, not a warning.
  4. S4 — An "Open settings" action on core rows. (a) No button: the row names the place, Settings › Core plugins › Bases; (b) a button that opens Obsidian's settings. Recommended: (a). Opening settings needs app.setting, which is not in obsidian.d.ts. The repo has learned to treat as unknown as on app as a red flag, and it cannot open the Core plugins page anyway. Community rows get no action of any kind, under either option F8.
  5. S5 — The "Install Dataview" link that ships today. The Library row of a Dataview collection says Install Dataview to run this collection… and links to the community directory (signed off in L9c, built in LibrarySection.paintInstallHint). That is a prompt toward a third-party install, and PRD F8 AC 5 says the capability list is the only mention. Recommended: replace it with the cause and a link to this screen: Needs Dataview, which is not active. What optional plugins add…. In the Workbench, This view requires the Dataview community plugin. becomes This collection needs Dataview, which is not active. This changes a signed-off L9c state, so it needs your yes and a decision-log entry (L12e).
  6. S6 — Whether metadata-menu is on the list at all. Story Forge never detects it. It reads the FileClass files that metadata-menu writes. Recommended: list it, honestly worded: what it adds is a form for editing FileClasses, and Story Forge works the same without it. Leaving it out would hide the one community plugin whose format the editor depends on, which is the question gap-analysis G14 asks to answer.

What this commits us to

When signed off, T7.4 builds one modal (CapabilitiesModal) fed by the detections that already exist: getBasesCapability, getDataviewApi, getDvSettings and the FileClass cache. No new plugin detection, and no app.plugins read beyond the two sanctioned casts in EngineRegistry.ts. openCapabilities in main.ts opens it, and the first-run check uses a new dismissedHints id. If S2 and S5 are accepted: the hint text changes, the Workbench Enable Bases button and the Library Install Dataview link go, and their cause texts stay. Not in scope: detecting further plugins, install buttons, version checks or links to plugin pages.
