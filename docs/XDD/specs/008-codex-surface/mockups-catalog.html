Story Forge — Collections from the repo · catalog browser L10a–L10i · follow-up to P18 · draft for sign-off

Why this page exists. mockups-library.html P18 (signed off) says: if the catalog browser needs more than a list of rows with an Install button, draw it as L10 before it is coded. T7.2 shipped src/catalog/BrowseOfficialModal.ts without that drawing, and its sf-catalog-* classes have no rules in styles.css. In Obsidian the modal is a stack of unframed lines, and the note source runs off the right edge. Two questions came back: the styling is bad, and what does it look like with more than one entry? This page answers both. It is the gate for the restyle. Nothing here changes what install, update or refusal do. They stay as T7.2 built them in CatalogService.

How to read this file. Light theme is the default. The Dark / Light toggle (top right) switches every figure, and L10i is always dark. Tokens and scaffolding come from mockups-library.html. Tags: T7.2 = shipped behaviour, drawn as it is; Q# = proposed here, not decided until you sign it off. Seed catalog: Scenes with this note is the one real entry (catalog/scenes-with-this-note.md). The other seven are invented to show how the browser scales across Bases, Dataview and DataviewJS. Paths assume the default Folder for collections from the repo, 00 Meta/Bases.

Proposals — your answer needed (recommended default in each)

  1. Q1 — Layout: two panes, or expand in place. (a) Two panes: the list on the left, the selected entry's detail on the right (the sf-catalog-split T7.2 already builds). (b) Expand in place: the detail opens under its row, like configure in the Library (L3). Recommended: (a). The list stays in view while you compare entries, and a long query never pushes the other rows off screen. Below about 560px the panes stack: the list fills the modal, and choosing a row opens its detail with ← All collections to go back (L10h).
  2. Q2 — Finding an entry. (a) search only; (b) search plus an engine filter (All · Bases · Dataview · DataviewJS, each with its count); (c) category group headers (Characters, Scenes…). Option (c) needs a new sf-category field in every catalog note and in build-catalog.mjs. Recommended: (b), list in catalog order, no categories. The engine is the one thing a user filters on for trust (code or no code), and we already have it. Search matches the name and the description, like Import a collection. Show the search and the filter only when the catalog has more than 5 entries. With 1 to 5 entries (L10a) they are noise.
  3. Q3 — Selection on open. (a) nothing selected, and the detail pane says what to do; (b) the first entry auto-selected (T7.2 today). Recommended: (a). Auto-select previews an entry you did not choose and puts its Install one keypress away. It also leaves a selection hidden when a search filters that row out. Focus starts in the search field, or on the first row when there is no search field.
  4. Q4 — Where the action and its feedback live. (a) only in the detail pane: the row shows status text (Installed, Update available, or nothing), and the one Install / Update button and its result sit under the entry you are reading. (b) T7.2 today: a button in every row plus one feedback box at the top of the modal. Recommended: (a). You install what you have read, never a row you only glanced at. A refusal appears next to the entry it is about, not above a list where it can belong to any row. And no button is nested inside a clickable row (one control per row is cleaner for keyboard and screen readers). At 400px the button is on the detail screen.
  5. Q5 — The query. (a) the query block only (the dataview / dataviewjs fence body, or the .base YAML), wrapped, at most about 10 lines high with its own scrolling; (b) the whole note, as today; (c) collapsed behind Show query. Recommended: (a). The note's frontmatter and prose repeat the name and description shown above it. Wrapping means the page never scrolls sideways. It stays visible rather than collapsed because "Safe: declarative query, no code." should sit next to the thing it vouches for. The whole note is still what gets written, and the destination line says so.
  6. Q6 — Checksum and provenance. Today every row and the preview print official · curated and sha256:3db2497… as primary text. Recommended: drop both from rows and from the detail header. Everything in this modal is from the repo, so the provenance line says nothing here. The Library already calls it from repo once it is installed. Source file, version and checksum go in a collapsed Details line at the bottom of the detail pane (L10d shows it open). Drop the checksum completely is the alternative: it is for bug reports, not for deciding.
  7. Q7 — Wording changes (everything else on this page uses T7.2's text): Recommended: (1) Success: Installed successfully. → Installed to 00 Meta/Bases/<file>. It is in Library › Collections. An update says Updated 00 Meta/Bases/<file>. (2) DataviewJS button: Install → Review and install…, because it opens the consent dialog first (the ellipsis signals a dialog). (3) Engine pills use the Library's product names Bases, Dataview, DataviewJS, not dataview-dql. (4) Detail placeholder: Select a collection to see what it shows and where it goes. (5) No search match: No collections match "<text>".
  8. Q8 — Machine-worded refusals. Three refusals already read well (Not updated: … was edited…, Not installed: … already exists…, … could not read …) and stay word for word. The others reach the user as developer strings: checksum mismatch: expected …, got …, consent declined, materialise failed: …, persist failed: …, store read failed: …. Recommended: one sentence each, in the same Not installed: … form, with the raw reason kept as a faint second line so a bug report still carries it (table under L10f). Consent declined is not an error. Show it as a neutral note: Not installed. You closed the review, so nothing was written.

What this commits us to

When signed off, T7.2's restyle builds exactly this. It is a rendering change in BrowseOfficialModal plus sf-catalog-* rules in styles.css on Obsidian variables (--background-*, --text-*, --interactive-accent), so both themes follow the user's theme. CatalogService stays as it is, apart from the refusal wording if Q8 is accepted. The import modal (sf-picker-*) is the sibling. This browser reuses its search field, sub-line and footer classes so the two look alike. It also uses the Library's engine labels (ENGINE_LABEL) in both. No network, categories, diffs, ratings or uninstall here: removing stays in Library › Collections.
