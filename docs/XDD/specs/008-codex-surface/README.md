| 2026-08-06 | **T5.4: a render mid-write is *corrected*, never *deferred* — user-initiated renders stay immediate** (orchestrator ruling, against the review's own suggested fix) | The code-quality review found a real gap and proposed the wrong fix, and the difference is the decision worth keeping. `_reconcile`'s defer covers only the two **debounced** paths (`active-leaf-change`, `metadataCache.changed`); the other eleven `_render()` call sites are user-initiated — dock, fullscreen, back, close, collection switch, Card pick, timeline mode, hint dismiss, section collapse. A click's mousedown blurs the box, which fires the `change` that starts the commit, and the click handler then renders **in the same tick**, rebuilding every control from a `metadataCache` the unresolved write has not reached: the user watches their own edit revert, with no undo journal to get it back (#17). **The review proposed routing those call sites through `_reconcile` so they defer too. Rejected** — that makes "close" and the dock toggle do nothing until I/O completes, and a UI that ignores clicks is worse than one that briefly shows a stale value. Instead the view keeps a small `_inFlight` map (field → value on its way to the file) and *overlays* it on the cache read in `_renderFields`. **Owned by the view, not the `FieldCommitter`**, because a render REPLACES the committer — which is also why the old `_commits?.busy` guard was itself unsound after any mid-write render. An entry lives only while its write is unresolved, so the overlay can never shadow a later external edit. Nothing clears `_inFlight` on the inspect path and deliberately still does not: the write really is in flight, and returning to that note before it lands must still show the overlay. The state stays honest; the guard narrows the decision. No debounce, no write queue, no new write path. |

### Settled before the spec (do not re-open)

- **Two axes, never one.** *Collection* = what is shown (a query). *Card* = how an entry is drawn.
  The word "view" is retired from the UI.
- **Obligation is per tab, not per interface.** The Codex tab is substitutable; the management tabs
  (Timeline, Plotgrid, Plotlines, Board) are deliberately opinionated and configurable.
- **Selection is by tag**; folders only ever *exclude*, from settings.
- **Add-ons are never required** — native fallback is a hard requirement, not a courtesy.
- **Field types in scope:** `Input`, `Select`, `Multi`, `MultiFile`, `Number`, `File`, `Boolean`,
  `Date`. Out: `Lookup`, `Formula`, `Canvas` — metadata-menu *computes* those, so without it there is
  no engine behind them.

### Known defect to fix here

`CatalogService` materialises a `.base` into the vault **and** persists a copy as `record.source`.
Drift is computed only over the store copy, so editing the vault file raises no drift — yet
`_openCodex` opens exactly that file. ADR-0003 removes the second copy.
