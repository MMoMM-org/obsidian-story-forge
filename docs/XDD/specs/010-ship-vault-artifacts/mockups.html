Story Forge — Story files · setup and update S1–S6 · spec 010 T3.1 · draft for sign-off

Why this page exists. Spec 010 ships the FileClasses, templates and schema reference inside main.js and writes them into the vault only when you ask (PRD F2, F4). The SDD (ADR-42, CON-6) puts the UI behind this sign-off: a Story files group in Settings › Scope, one Set up story files dialog for both setup and update, a result notice, and a pointer on the capability screen. Nothing here is coded yet. Once you sign off, T3.2–T3.4 build what is drawn here, and any divergence is raised before it is coded.

How to read this file. Light theme is the default; the Dark / Light toggle (top right) switches every figure. Tags: SDD / PRD = already decided in solution.md or requirements.md, drawn as decided; proposed or D# = invented here, not decided until you sign it off. Every UI string that is not existing code or a spec quote is marked proposed. An amber bar on the left edge of a settings row or capability row marks something new. Shipped set (from dist/artifact-index.json): 27 files — FileClasses 11 (8 fc-*.md + the value lists fc-armor, fc-combat-skills, fc-magical-abilities), Templates 7, Schema reference 9 (README.md + 8 types). Default folders 00 Meta/FileClasses, 00 Meta/Templates, 00 Meta/Schema; Excluded folders default 00 Meta.

Decisions for sign-off (recommended default in each)

  1. D1 — Where the group and status line sit. A new Story files group in the Scope tab, directly under Vault folders: Templates folder, Schema reference folder, then a Set up story files row whose description is the status line and whose button is Set up story files…. FileClasses folder stays in Vault folders, and its description gains one sentence pointing at the setup. Recommended as drawn in S1. Alternative: a status line of its own above the button — one more row for the same information.
  2. D2 — One button label in every state. The button always reads Set up story files… (same as the command), also when updates are available. The status line carries the state. Recommended. One name for one dialog. Alternative: Review updates… when anything is updatable, which makes the command and the button disagree.
  3. D3 — What the status line counts. N updates available counts update items; N missing counts missing items; both appear together when both exist. skip-exists (your own file) and skip-edited (you edited it) are never counted as something to do — at most a faint aside (1 edited file left as it is). Not set up = no records at all; a partial setup says 9 of 27 story files set up. Recommended. The settings never nag about a file you chose to keep. The aside is optional; drop it if you want the line shorter.
  4. D4 — Sets collapsed, with counts; expand per set. Each set is a card: checkbox, name, file count, target folder, a row of action chips (11 create, 2 update, 1 edited…) and Show files. Fresh vault: all three collapsed. Mixed: a set opens on its own when it holds anything you might want to look at (skip-*, missing, unreadable, refused); sets with only create / update / up to date stay collapsed. Recommended. 27 rows at once is a wall; the chips already answer "what happens", and the rows are one click away.
  5. D5 — Per-file choice. Every row that will write has its own checkbox: Create and Update rows start ticked, a Missing row starts unticked with the label Set up again (PRD F4.5). The set checkbox ticks or unticks all of its writable rows and shows a dash when only some are ticked. Rows that write nothing (Up to date, Not installed, Not updated, Unreadable, Damaged) have no checkbox. Recommended. Covers the PRD's Should per-file choice in the update list and re-set-up of a missing file with one rule.
  6. D6 — The primary button counts what it writes. Set up 27 files when everything is a create; Update 3 files when everything is an update; Set up and update 10 files when mixed (ticked Set up again rows count as set up). With nothing ticked it reads Nothing to set up, disabled. Second button: Cancel. Focus starts on the first set's checkbox, never on the primary button. Recommended. The count is the last check before writing; Enter on open never writes.
  7. D7 — Folder changes in the dialog. The folder field per set is the same folder suggester as in settings. A change is saved to the matching setting only when you confirm with the primary button; the set's plan is still recomputed on change, as a preview only (SDD Primary Flow step 4). Cancel (and Escape, ✕) changes nothing: no file is written and no setting is changed. Decided (O1, 2026-11-19) — this replaces the SDD's "saved when you leave the field".
  8. D8 — "Setting now points to …" shown once per set. When the set's files were set up in another folder than the setting now names, the set card carries one grey note above its rows; the rows show the record path. Recommended. Seven identical row notes are noise. A per-row note appears only for a file whose record folder differs from the rest of its set.
  9. D9 — Folder-not-excluded warning. An amber note inside the set card, wording proposed in S4, with a button Add to excluded folders that changes the Excluded folders setting only (no file written). Setup stays allowed. Recommended with the button. Alternative: text only, naming Settings › Scope › Excluded folders. Either way the warning does not block.
  10. D10 — Result notice and truncation. One Obsidian notice. Success only: one line, hides after the usual few seconds. Anything skipped or failed: the notice stays until clicked; it lists at most 5 reason lines (failed first, then skipped), then and N more. Open Set up story files again to see each file. Every refusal and failure is also logged with console.debug("[StoryForge] …"). Recommended. "See the console" does not work on mobile; the dialog does, and it shows every skipped file's state again. Failures are re-offered there as Create.
  11. D11 — Capability screen pointer. A Story files row first in the body, in a group of its own (Story Forge · written only when you ask), with a status and the button Set up story files…. The button closes the capability screen (first run: recorded as seen) and opens the setup dialog. The screen writes nothing. Recommended. For a new user this is the one thing on that screen that changes what they see. Alternative: the row last, after the community plugins.
  12. D12 — Names. Set names FileClasses, Templates, Schema reference; settings Templates folder and Schema reference folder; command Set up story files; refusal texts word for word from managedFileWriter / executePlan (the spec 008 prefixes Not installed: / Not updated:). Recommended. "Schema reference folder" matches the set name; "Schema folder" is the shorter alternative.

Resolved questions · beyond D1–D12, decided 2026-11-19

  1. O1 — Cancel and a changed folder. Resolved: a folder change is saved only when you confirm with the primary button. Cancel changes nothing (no file, no setting). The plan is still recomputed on change, as a preview only (D7).
  2. O2 — Partly set up status. Resolved: names the sets not set up, e.g. FileClasses and Schema reference set up · Templates not set up (proposed wording); the 9-of-27 count is kept as an aside (S1b, S6).
  3. O3 — Value lists. Resolved: independent rows, not tied to fc-character-fantasy.md (S2b).
  4. O4 — Refusal verb. Resolved: keep "Not installed" / "Not updated" word for word (S3).
  5. O5 — Missing row checkbox. Resolved: visible label Set up again (S3 and the action table).
  6. O6 — Skipped lines in the notice. Resolved: up to 5 skipped or failed files listed by name (S5c).
  7. O7 — Name of the capability screen. Proposed 2026-11-20 after review: What optional plugins add became wrong once Story Forge's own story files sit first on it. New name What Story Forge can use, used for the title, the footer line and every link that opens it (Library tab, Dataview hints). The intro adds "and best with its story files". The command and the seen-flag do not change.
  8. O8 — Library tab hint. Proposed 2026-11-20 after review: the first settings page shows a hint while no story file is set up (S7), with Don't show again.
  9. O9 — metadata-menu in the Properties panel. Proposed 2026-11-20 after review: the row names that metadata-menu brings the FileClass option lists into Obsidian's Properties panel. Observed by the maintainer; metadata-menu's own docs do not describe it, so the live walk (T3.5) checks it before the wording ships.
