Story Forge — undo journal mockups (spec 009, U1–U11)

Sign-off gate for Phase 4 (T4.1, CON-8). Once signed off, this file and its notice wording are binding (resolves OQ-3); the implementation follows it, never the other way round.

How to read this file. Every state from the SDD's UI Visualization Guide (U1–U11) has its own section with the rendered state and a behaviour note (enabled/disabled, ARIA, focus). Existing chrome is copied from styles.css with its real class names (sf-ws-head, sf-ws-toggle, sf-zoom-bar, sf-vhead, sf-icons, sf-pin-btn, sf-inspector-*); the new classes are sf-undo-group, sf-undo-tool and sf-undo-btn. Colours come only from Obsidian theme variables; use the Dark / Light toggle at the top right. Tags: SDD = text or behaviour fixed by the SDD; proposal = not specified, invented here for you to accept or change; decision needed = a choice the SDD explicitly leaves open. Notice texts are shown with the macOS key name (Cmd); on Windows and Linux they read Ctrl (ADR-49).

Open points for sign-off

  1. P1 — Unexpected error notice (U9). decision needed A rejected undo/redo is console-only today (wireUndoJournal, T2.7). Proposal: also show “Couldn't undo: an unexpected error occurred. See the developer console for details.” Alternative: keep console only.
  2. P2 — Look of the Anvil controls (U1–U3). proposal The SDD fixes the markup (toolEl spans) but not the look. Proposed: a small pill like the zoom bar, two bordered 22×20 cells, placed after the zoom slot at the far right of the header.
  3. P3 — Disabled look in the Workbench (U4). proposal The SDD says disabled = --text-faint, but pin and edit already rest at --text-faint, so a disabled ↶ would look exactly like an enabled pin. Proposed: enabled ↶ ↷ use --text-muted; disabled uses --text-faint plus opacity: .55 and no hover background. Also a thin separator between ↶ ↷ and 📌 ✎.
  4. P4 — Narrow Anvil header (U3). decision needed .sf-ws-head does not wrap today, so at narrow widths the right end (zoom, and then ↶ ↷) is pushed out of the leaf. Proposed: allow the header to wrap, and keep zoom + ↶ ↷ as one cluster that moves to a second row, right-aligned. The ↶ ↷ stay last.
  5. P5 — Note name in the refusal (U8). proposal The SDD says “Save or discard your edit first” + note name, without a format. Shown here as shipped: “Save or discard your edit first (Mara Stoneway)”. Alternative: “Save or discard your edit in Mara Stoneway first”.
  6. P6 — “Discard” has no control in the Workbench (U8). decision needed The Workbench has a Save button but no Discard; the only way to discard is to retype the old value (traced walkthrough 3). Options: keep the wording and accept this, word it as “Save your edit or undo it by hand first”, or add a discard affordance (out of scope for 009 unless you say so).
  7. P7 — Multi-field conflict sentence (U7). proposal The SDD gives only the rule (name up to three, then “and N more”). Shown as shipped: “Undo: A, B and C had changed since; Cmd+Shift+Z restores them.” It names fields but no values.
  8. P8 — The shortcut named in the conflict notice (U7). decision needed “Cmd+Shift+Z restores it” is only true when the Anvil or Workbench is the active view (ADR-37). After an undo from the command palette inside a Markdown note, Cmd+Shift+Z is the note editor's own redo. Options: keep the shortcut; or say “Redo restores it” / “Redo last change restores it”.
  9. P9 — Failed and vanished in one step (U9). decision needed Shipped: the outcome is failed and the notice does not name the vanished note (Phase 2 drift check, “decided together with U9”). Proposed: append the vanished sentence.
  10. P10 — Plural grammar (U9). proposal Shipped plural forms read “Couldn't undo the changes in 3 notes. It stays on the undo stack” and “Scene 4 no longer exists; its change was removed” even when Scene 4 had several changes. Proposed: “They stay …” and “its changes were …” when there are several changes.
  11. P11 — Settings texts (U11). proposal The SDD names the two rows and requires that the description mention copies of field values (AC-F7.9); the heading, both descriptions, the button label and its style are proposed here. Also: no confirmation on Clear (undo history is not story data), and the button is always enabled.
  12. P12 — Workbench outside-change cue (U10). proposal ADR-42 says what each field shows, not whether an updated field is highlighted. Proposed: no flash or highlight; the value just changes, as in the Anvil. The “← changed” tags in U10 are mockup annotations, not UI.
  13. P13 — No “running” look (component state diagram). proposal The SDD's state diagram has a Running state. Proposed: no visual change while an undo runs (it takes milliseconds); a second click while running is queued like any other request.

U1 — Anvil header, both enabled · Codex tab and Board tab

U2 — Anvil header, disabled states

Behaviour SDD ADR-50: disabled = aria-disabled="true" + muted look; no disabled attribute, and tabindex="0" stays, so a disabled control is still focusable and its tooltip “Nothing to undo” stays reachable. Activating a disabled control (click, Enter, Space) does nothing and shows no notice. The state updates from journal.subscribe in every open view without a reload (AC-F6.5). While work is pending on the top step's note (a draft, a write in flight) the controls stay enabled, so the click can explain itself with the U8 notice (AC-F6.4). Muted look: proposal P2.

U3 — Anvil header at narrow width decision needed P4

Implementation note for the proposal: the wrap needs a wrapper (or order) so the zoom slot and the undo group move together; the zoom slot's margin-left: auto moves to that wrapper. The Timeline bar (.sf-ws-tlbar) sits between strip and cluster and wraps like any other item. Alternative to discuss: keep no wrap and let only the tab strip scroll horizontally, as the Workbench's .sf-tabs already does.

U4 — Workbench header, enabled and disabled

Markup SDD ADR-50: two native button.sf-undo-btn[data-sf-undo] prepended to .sf-icons, each with its own registerDomEvent(click), aria-label = title; disabled = aria-disabled="true", never the disabled attribute. Native buttons give Enter/Space for free. The buttons are shown in both read-only and edit mode, and whether the Workbench follows or is pinned; the journal is global, so they show the same step as the Anvil (no per-surface labels, PRD Won't). Colours and the separator: proposal P3. The pin's own resting colour (--text-faint) is unchanged.

U6 — Notice: plain undo, plain redo

Behaviour: one Obsidian Notice per outcome, whatever the trigger (key, command, button). When the Anvil is open, its live region (.sf-ws-live, role=status, aria-live=polite) repeats the same text for screen readers. Nothing scrolls, opens or takes focus.

U7 — Notice: conflict

Value format ADR-49: strings in single quotes; lists joined with “, ”; an absent field reads “not set”; null reads “empty”; values cut at 40 characters with “…”. Example: “… is not set again. It had changed to 'Mara, Spark'; …”. Shortcut: “Cmd+Shift+Z” on macOS, “Ctrl+Shift+Z” elsewhere. See P8 about naming the shortcut at all.

U8 — Notice: “Save or discard your edit first”

Gotcha — focus moves on a button click (SDD Implementation Gotchas)

In the Anvil editor, clicking ↶ while the caret is still in a field blurs the field first:
  1. the blur fires change and commits the draft as its own step;
  2. the click then reaches the undo, which either meets that write still in flight → the U8 refusal naming that note, or, once it has landed, undoes the commit just made.
Correct by the stack model, but it means “click ↶ while typing” reverts your typing, not the step the tooltip named a moment earlier.

Finding — Phase 3 live test (docs/live-testing.md, step 4)

When undo comes from the command palette, opening the palette blurs the Anvil field, which commits the draft as its own step; “Undo last change” then reverts that step. No refusal appears. Mod+Z with focus outside the draft field also commits on blur. So the Anvil refusal is practically never reached; it stays as a cheap guard. In practice the U8 notice comes from the Workbench, whose fields keep their drafts until Save. The Phase 6 walk checks the Workbench refusal.

U9 — Notices: failures, vanished notes, nothing to undo, unexpected error

U10 — Workbench field after an outside change · ADR-42, closes #30

The outside change is an undo, a hand edit in the note, or a write from the Anvil. The tags on the right (“← changed”, state names) are mockup annotations, not UI (proposal P12: no highlight).

Rules ADR-42:
  • clean and saved take the file's value on every refresh; a saved field whose value changed returns to clean.
  • dirty keeps its draft; its stored value moves to the file's value, so restoring the old text (the only “discard”) lands on the current file value (AC-F9.6). In U10c, if the user retypes the original aliases, the field shows the file's aliases and becomes clean.
  • saving keeps its draft and its stored value; the write's own result settles it. error (red message, Save and Retry) is protected exactly like dirty.
  • A structural redraw (fields added or removed, FileClass change) that a protected field blocks is owed and runs as soon as the last protected field is clean/saved or the subject changes. Nothing is shown for it.
  • A pinned Workbench now refreshes too when its own subject changes (ADR-51); before, it ignored every change. Focus is never moved by a refresh; the caret stays in aliases.

U11 — Settings

Behaviour ADR-48:
  • Off: the file is deleted at once; nothing more is saved; this session's stacks stay in memory, so the buttons keep working until a restart. No notice proposal.
  • On again: the next change saves the file.
  • Clear: empties both stacks and removes the file; every ↶ ↷ in open views turns disabled; notice “Undo history cleared”. It is a deliberate action (CON-4). proposal P11: no confirmation, a normal (not red) button, always enabled even when the stacks are already empty. Alternative: a mod-warning button or a confirm step.

Notes on the SDD found while drawing

  • Disabled token vs neighbours. “--text-faint for disabled” equals the resting colour of .sf-pin-btn/.sf-edit-btn, so it cannot read as disabled in the Workbench (P3). The SDD also names --interactive-hover, while the sibling buttons use --background-modifier-hover; this mockup uses the latter.
  • “Tooltip reachable by keyboard” (ADR-50). A native title tooltip does not show on focus; keyboard users get the text only as the accessible name. Also, Obsidian draws its own tooltip from aria-label; with title as well, check live that no double tooltip appears (the existing toolEl already sets both).
  • Discard is named in the refusal but has no control in the Workbench (P6).
  • Shortcut in the conflict notice is only valid with a Story Forge view active (ADR-37 vs ADR-49, P8).
  • Error Handling table has no row for failed + vanished, which Phase 2 deferred to U9 (P9); and its Anvil-draft row is practically unreachable per the Phase 3 live test (U8).
  • Narrow header (U3). The table asks about wrapping, but .sf-ws-head has no flex-wrap today; this needs a CSS decision (P4).
