# General Memory

<!-- 2026-08-01 -->
- `ViewRecord` (src/store/types.ts) has a shared test factory — `makeDummyViewRecord()` in `test/helpers/viewFixtures.ts` — but only ~4 test files use it; most build the object literal inline, and several keep their own local `rec()`/`makeRecord()` helper. So adding a required field to `ViewRecord` has **no single choke point**: expect breakage scattered across ~20 files. Fix each file's local helper once rather than every call of it, and prefer extending `viewFixtures.ts` over adding a new local factory.

<!-- 2026-08-03 -->
- **Mockup sign-off is a hard gate, not a starting point for generalization.** Spec-008 T4.3: Hero's key facts were split into a uniform labelled-chip row instead of reproducing S91's exact two-slot `.hf` (middot-joined summary line) / `.hp` (flex-wrap pill row) structure. The generalization was defensible on the merits (it fit non-character kinds more evenly) but was still ruled out — a divergence from a signed-off mockup must be raised *before* coding, not shipped and reported afterward; the mockup is never re-synced to match code that already diverged. Rebuilt to match S91 exactly in `853bff1`.
- **A generalization applied uniformly across kinds is itself an unsigned design decision**, by the same standard, if the mockup only ever shows a worked example for ONE kind. Spec-008 T4.3's Hero applies the signed-off character rule (first two facts → summary line, third fact → pill row) mechanically to location/object/lore too — no signed-off figure shows those kinds with real facts populated, so that extension needed (and got, as a separate open item) its own explicit user ruling rather than being resolved unilaterally just because "it's the same rule, applied generically."
